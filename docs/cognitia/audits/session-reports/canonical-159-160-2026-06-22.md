## 2. What was on `alta-90`, and the integrity problem

`alta-90` carried two distinct bodies of work:

| Artifact                                                                  | Origin | Verdict                                                                      |
| ------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------- |
| `packages/agents/src/gtm-os/integration/{runPacket,adapters}.ts` (+ test) | #159   | **KEEP** — a genuine read-model that _composes_ the real B1–B6 lane modules. |

| `apps/web/src/lib/gtmCommandCenterViewModel.ts` (1,197 lines)             | #160   | **REJECT** — a hand-authored _structural mirror_.                            |

The rejected view-model states its own intent in its header:

> _"this file does NOT import `@cognitia/agents`. Instead it faithfully
> reproduces the tested lane semantics structurally … so the route is a true
> mirror of the authoritative implementations."_

That is exactly the failure mode requirement #3 forbids: it re-implements B1–B6
(signal weights, fail-closed rules, idempotency, packets) in `apps/web` instead
of running the real modules. A mirror can silently drift from the code it claims
to prove. It is also unnecessary — the canonical base already demonstrates the
correct pattern: `apps/web` depends on `@cognitia/agents` (`workspace:*`) and the
existing `/gtm-os-integrated-demo` route loads a **server-only adapter** that runs
the real modules.
